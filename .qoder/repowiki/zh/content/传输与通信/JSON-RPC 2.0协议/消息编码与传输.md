## 引言
本文档详细阐述了Go MCP SDK中JSON-RPC 2.0消息的编码与传输机制。核心实现位于`internal/jsonrpc2`包中，通过`wire.go`和`frame.go`文件定义了消息的序列化、反序列化以及在不同传输协议下的帧结构。`mcp/transport.go`文件则提供了高层的传输接口，将编码后的消息通过多种传输方式（如Stdio、HTTP、SSE等）进行发送。本系统确保了消息在不同环境下的可靠传递，并支持批量处理和空值处理。

## 消息编码机制

`internal/jsonrpc2`包中的`EncodeMessage`和`DecodeMessage`函数是JSON-RPC 2.0消息编解码的核心。`EncodeMessage`函数将一个`Message`接口实例（可以是`Request`或`Response`）转换为符合JSON-RPC 2.0规范的JSON字节流。它首先创建一个`wireCombined`结构体，该结构体包含了JSON-RPC消息的所有可能字段（版本号、ID、方法、参数、结果、错误）。然后，通过调用`msg.marshal(&wire)`将具体的消息内容（请求或响应）填充到`wireCombined`结构体中，最后使用`json.Marshal`将其序列化为JSON字节流。

`DecodeMessage`函数则执行相反的操作，它将接收到的JSON字节流解析为一个`Message`实例。首先，它将JSON数据反序列化到`wireCombined`结构体中，并验证`jsonrpc`版本号是否为"2.0"。接着，根据`Method`字段是否为空来判断是请求还是响应。如果`Method`不为空，则构造一个`Request`对象；否则，构造一个`Response`对象，并检查`Error`字段以确定是否存在错误。

## 传输帧结构

`frame.go`文件定义了`Framer`接口，用于处理不同传输协议下的消息帧结构。该接口提供了`Reader`和`Writer`方法，将底层的字节流读写器包装成消息级别的读写器。

目前实现了两种帧格式：
1.  **RawFramer**: 采用原始JSON格式，不添加任何额外的头部信息。消息的边界由JSON解码器的`Decode`方法隐式确定。这种格式依赖于JSON数据的完整性，适用于简单的流式传输。
2.  **HeaderFramer**: 采用HTTP风格的头部信息，即在每个JSON消息前添加`Content-Length`头部。`headerReader`在读取时会先解析头部以获取消息长度，然后精确读取指定长度的字节，最后进行JSON解码。`headerWriter`在写入时会先写入`Content-Length`头部，再写入JSON数据。这种格式能明确地分隔消息，避免了因流式传输导致的粘包问题，是LSP等协议的标准格式。

## 传输层集成

`mcp/transport.go`文件定义了`Transport`和`Connection`接口，作为高层应用与底层消息传输之间的桥梁。`Transport`接口的`Connect`方法用于建立一个逻辑上的JSON-RPC连接，返回一个`Connection`实例。`Connection`接口则提供了`Read`和`Write`方法，用于在连接上收发`jsonrpc.Message`。

不同的传输方式通过实现`Transport`接口来工作。例如：
-   `StdioTransport` 使用标准输入/输出。
-   `IOTransport` 使用任意的`io.ReadCloser`和`io.WriteCloser`。
-   `SSEServerTransport` 和 `StreamableServerTransport` 处理基于HTTP的SSE和流式传输。

在`Write`方法的实现中，编码后的消息会通过`jsonrpc2.EncodeMessage`转换为字节流，然后根据具体的传输方式（如`ioConn.Write`）写入底层的`io.ReadWriteCloser`。`LoggingTransport`等中间件可以在消息发送前进行日志记录，它通过包装`Connection`并在`Write`时调用`jsonrpc2.EncodeMessage`来获取消息内容。

## 实际报文示例

以下是一些符合JSON-RPC 2.0规范的报文示例：

**通知消息 (Notification)**
```json
{"jsonrpc":"2.0","method":"alive"}
```
此消息没有`id`字段，表示一个通知，发送方不期望收到响应。

**请求消息 (Request)**
```json
{"jsonrpc":"2.0","id":"msg1","method":"ping"}
```
此消息包含`id`和`method`字段，表示一个请求。接收方应返回一个`id`相同的响应。

**响应消息 (Response)**
```json
{"jsonrpc":"2.0","id":"msg2","result":"pong"}
```
此消息包含`id`和`result`字段，是对请求的正常响应。

**错误响应 (Error Response)**
```json
{
    "jsonrpc":"2.0",
    "id":3,
    "error":{
        "code":0,
        "message":"computing fix edits"
    }
}
```
此消息包含`id`和`error`字段，表示请求处理失败。`result`字段不存在。

**批量消息 (Batch)**
```json
[
    {"jsonrpc":"2.0","id":"1","method":"sum","params":[1,2,4]},
    {"jsonrpc":"2.0","id":"2","method":"notify_hello","params":[7]},
    {"jsonrpc":"2.0","id":"9","method":"subtract","params":{"subtrahend":2,"minuend":4}}
]
```
一个JSON数组，包含多个独立的请求或通知。

## 自定义与调试

开发者可以通过多种方式自定义编码逻辑或注入调试日志：

1.  **自定义编码**: 可以通过实现`jsonrpc2.Message`接口来创建自定义的消息类型，并在`marshal`方法中定义其序列化逻辑。
2.  **调试日志**: `LoggingTransport`提供了一个现成的日志记录方案。它在`Write`和`Read`方法中调用`jsonrpc2.EncodeMessage`来获取消息的JSON表示，并将其写入指定的`io.Writer`。开发者可以创建自己的`Transport`或`Connection`包装器，实现类似的功能，例如将消息记录到文件或发送到监控系统。
3.  **自定义传输**: 通过实现`Transport`接口，可以创建新的传输方式。例如，`examples/server/custom-transport`中的`IOTransport`就是一个自定义实现，它使用`bufio.Reader`和`io.Writer`进行消息的读写。
