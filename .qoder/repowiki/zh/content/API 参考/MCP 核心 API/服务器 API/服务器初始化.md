## 简介
MCP服务器初始化过程是构建MCP服务的核心环节，主要通过`mcp.NewServer`函数实现。该过程涉及`Implementation`结构体的创建、`ServerOptions`配置参数的验证与默认值设置，以及服务器实例的最终构建。本文档详细说明了服务器初始化的各个关键环节，包括调用流程、参数验证、默认值处理、panic条件以及实际使用示例，为开发者提供全面的指导。

## NewServer函数调用流程
`mcp.NewServer`函数是创建MCP服务器实例的入口点，其调用流程遵循严格的验证和初始化顺序。函数接收`*Implementation`和`*ServerOptions`两个参数，并返回一个`*Server`实例。

调用流程如下：
1. 首先验证`Implementation`参数是否为nil，若为nil则直接panic。
2. 创建一个`ServerOptions`的副本，以防止外部修改。
3. 对`ServerOptions`中的各项配置进行验证和默认值设置：
   - 验证`PageSize`，若为负数则panic，若为0则设置为`DefaultPageSize`。
   - 验证`SubscribeHandler`和`UnsubscribeHandler`的配对关系。
   - 若`GetSessionID`为nil，则使用默认的`randText`函数。
   - 若`Logger`为nil，则使用`ensureLogger`创建一个默认日志记录器。
4. 最后，使用验证和处理后的参数初始化`Server`结构体并返回。

此流程确保了服务器在创建时就处于一个有效且一致的状态。

## Implementation结构体的必要性
`Implementation`结构体是MCP服务器身份和元数据的核心表示，其在服务器初始化中扮演着不可或缺的角色。

该结构体包含三个关键字段：
- `Name`：服务器的程序化名称，用于逻辑标识。
- `Title`：服务器的显示名称，用于用户界面展示。
- `Version`：服务器的版本号。

`Implementation`结构体的必要性体现在：
1. **身份标识**：它为服务器提供了唯一的身份标识，使客户端能够识别和区分不同的MCP服务器。
2. **元数据传递**：在初始化过程中，服务器会将自身的`Implementation`信息通过`InitializeResult`发送给客户端，这是协议规定的必要步骤。
3. **非空要求**：`NewServer`函数明确要求`Implementation`参数不能为nil，这保证了每个服务器实例都必须有明确的身份定义。

## ServerOptions配置参数详解
`ServerOptions`结构体定义了MCP服务器的可配置行为，其各项参数在初始化过程中被逐一处理。

### 核心配置参数
- **Logger**：用于记录服务器活动的日志记录器。若未提供，将使用`ensureLogger`创建一个默认的丢弃日志记录器。
- **PageSize**：列表方法（如`ListTools`）单页返回的最大项目数。若为0，将默认为`DefaultPageSize`（1000）；若为负数，则会触发panic。
- **KeepAlive**：心跳检查的间隔时间。若设置为非零值，服务器将定期向客户端发送ping请求，若客户端无响应，则自动关闭会话。
- **SubscribeHandler** 和 **UnsubscribeHandler**：处理资源订阅和取消订阅的回调函数。这两个处理器必须成对出现，否则会触发panic。

### 功能启用标志
- **HasPrompts**、**HasResources**、**HasTools**：这些布尔标志用于在服务器未注册任何相关功能时，仍然向客户端通告其支持这些功能的能力。

### 会话管理
- **GetSessionID**：提供下一个会话ID的函数。若未提供，将使用`randText`生成一个随机的26字符ID。

这些参数之间存在相互依赖关系，例如`KeepAlive`依赖于`Ping`方法的实现，而`SubscribeHandler`和`UnsubscribeHandler`必须同时存在或同时不存在。

## 初始化过程中的panic条件
`mcp.NewServer`函数在初始化过程中设置了多个panic条件，以确保服务器配置的正确性。

主要的panic条件包括：
1. **Implementation为nil**：这是最基础的检查，若`Implementation`参数为nil，函数将直接panic，因为服务器必须有明确的身份。
2. **SubscribeHandler与UnsubscribeHandler不匹配**：
   - 若`SubscribeHandler`不为nil而`UnsubscribeHandler`为nil，会panic。
   - 若`UnsubscribeHandler`不为nil而`SubscribeHandler`为nil，会panic。
   这确保了资源订阅功能的完整性。
3. **PageSize为负数**：若`ServerOptions.PageSize`小于0，函数将panic，因为页大小不能为负值。

这些panic条件是防御性编程的体现，它们在服务器创建的早期阶段就捕获了严重的配置错误，防止了后续运行时可能出现的不可预测行为。

## 服务器初始化代码示例
以下是一个正确初始化MCP服务器实例的代码示例：

```go
// 创建Implementation实例
impl := &mcp.Implementation{
    Name:    "greeter",
    Version: "v0.0.1",
    Title:   "Greeter Server",
}

// 创建ServerOptions实例
options := &mcp.ServerOptions{
    Instructions: "Say hello to the user",
    Logger:       slog.Default(),
    PageSize:     500,
    KeepAlive:    30 * time.Second,
}

// 创建服务器实例
server := mcp.NewServer(impl, options)
```

此示例展示了如何创建`Implementation`和`ServerOptions`，并调用`NewServer`来创建服务器。注意，`SubscribeHandler`和`UnsubscribeHandler`在此示例中未设置，因为该服务器不提供资源订阅功能。

## 最佳实践与常见错误
### 最佳实践
1. **始终提供Implementation**：确保`Implementation`的`Name`和`Version`字段被正确设置。
2. **合理设置PageSize**：根据预期的负载和性能要求设置合适的页大小。
3. **使用自定义Logger**：提供一个有意义的日志记录器，以便于调试和监控。
4. **成对设置订阅处理器**：如果需要资源订阅功能，务必同时提供`SubscribeHandler`和`UnsubscribeHandler`。

### 常见错误
1. **忽略Implementation**：忘记创建`Implementation`实例或将其设为nil，这将导致程序panic。
2. **PageSize设置错误**：将`PageSize`设置为负数，这会触发panic。
3. **订阅处理器不匹配**：只设置了`SubscribeHandler`而没有设置`UnsubscribeHandler`，反之亦然。
4. **重用options参数**：在调用`NewServer`后修改`options`参数，由于函数内部会复制该参数，因此外部修改无效。

遵循这些最佳实践并避免常见错误，可以确保MCP服务器的稳定和可靠运行。
