## 简介
本文档详细描述了 `mcp.Tool` 结构体的设计与实现，该结构体是 Model Context Protocol (MCP) 中用于定义工具的核心数据模型。文档深入解析了其各个字段的定义、语义含义、使用约束以及在协议传输过程中的表现形式。重点说明了名称字段的显示优先级规则、描述字段对LLM理解的作用、输入输出模式对JSON Schema 2020-12草案的支持要求，以及通过 `AddTool` 方法进行自动验证的底层机制。同时，文档还涵盖了 `Meta` 字段的通用用途和 `ToolHandler` 与 `ToolHandlerFor` 处理工具调用的底层原理。

## 核心结构体定义

`mcp.Tool` 结构体是MCP协议中用于描述服务器端可用工具的核心数据结构。它定义了工具的元数据、功能描述、参数和返回值的结构约束，是客户端发现和调用服务器功能的基础。

## 字段语义与约束

`mcp.Tool` 结构体包含多个关键字段，每个字段都有明确的语义和使用约束。

- **Name**: 用于程序化或逻辑使用的工具名称。在没有提供 `Title` 的情况下，可作为显示名称的后备选项。
- **Title**: 专为UI和最终用户上下文设计的字段，旨在优化为人类可读且易于理解的形式，即使是对领域特定术语不熟悉的用户也能理解。
- **Description**: 对工具的人类可读描述。此字段可用于客户端提升LLM对可用工具的理解能力，可视为对模型的“提示”。
- **InputSchema**: 持有一个JSON Schema对象，定义了工具的预期参数。该字段必须非空且其类型必须为 "object"。
- **OutputSchema**: 可选地持有一个JSON Schema对象，定义了工具返回值的结构。如果存在，其类型也必须为 "object"。
- **Annotations**: 可选的附加工具信息，其中 `Annotations.Title` 在显示时具有特定的优先级。

## 显示优先级规则

在确定工具的显示名称时，遵循一个明确的优先级顺序。该规则确保了在不同上下文中都能呈现最合适的名称。

显示名称的优先级顺序为：`Title` > `Annotations.Title` > `Name`。这意味着系统首先尝试使用 `Title` 字段进行显示。如果 `Title` 未提供，则检查 `Annotations` 结构体中的 `Title` 字段。只有当这两个字段都不存在时，才会回退到使用 `Name` 字段作为最终的显示名称。

## JSON Schema 支持要求

`InputSchema` 和 `OutputSchema` 字段对JSON Schema标准有严格的要求。这些字段用于定义工具参数和返回值的结构，是确保数据正确性和类型安全的关键。

从服务器端看，这些字段可以设置为任何能JSON序列化的有效JSON Schema值。然而，当使用 `AddTool` 方法添加工具时，情况有所不同。`AddTool` 方法会自动对输入和输出进行验证，因此它要求Schema必须是SDK能够理解的草案版本。目前，SDK使用 `github.com/google/jsonschema-go` 库进行推断和验证，该库仅支持JSON Schema 2020-12草案。如果开发者希望使用其他草案版本或进行自定义验证，则应直接使用 `Server.AddTool` 方法。

## SDK 自动验证机制

当使用 `AddTool` 方法向服务器添加工具时，SDK会通过 `github.com/google/jsonschema-go` 库自动执行输入和输出的验证。这一机制极大地简化了开发者的负担，确保了工具调用的健壮性。

`AddTool` 是一个泛型函数，它接受一个 `ToolHandlerFor[In, Out]` 类型的处理器。在内部，`AddTool` 会调用 `toolForErr` 函数，该函数负责：
1.  推断 `In` 和 `Out` 类型的JSON Schema（如果工具定义中未提供）。
2.  解析Schema以进行验证和默认值应用。
3.  创建一个包装器函数，该函数在调用实际处理器之前，会自动对传入的 `Arguments` 进行反序列化和验证。
4.  在处理器返回后，对输出值进行序列化，并根据 `OutputSchema` 进行验证。

如果输入验证失败，`AddTool` 会直接返回一个 `jsonrpc2.ErrInvalidParams` 错误，阻止无效请求到达业务逻辑层。这确保了工具处理器接收到的输入始终是有效的。

## 结构体实例化与序列化

`mcp.Tool` 结构体的实例化通常在服务器初始化时完成。一个典型的实例化代码示例如下：
```go
tool := &mcp.Tool{
    Name:        "get_weather",
    Title:       "获取天气信息",
    Description: "根据城市名称查询当前天气状况。",
    InputSchema: &jsonschema.Schema{
        Type: "object",
        Properties: map[string]*jsonschema.Schema{
            "city": {Type: "string", Description: "城市名称"},
        },
        Required: []string{"city"},
    },
    OutputSchema: &jsonschema.Schema{
        Type: "object",
        Properties: map[string]*jsonschema.Schema{
            "temperature": {Type: "number", Description: "温度，单位摄氏度"},
            "condition":   {Type: "string", Description: "天气状况，如晴、雨、多云"},
        },
    },
}
```

在MCP协议的传输过程中，该结构体将被序列化为JSON格式。典型的JSON序列化输出如下：
```json
{
  "name": "get_weather",
  "title": "获取天气信息",
  "description": "根据城市名称查询当前天气状况。",
  "inputSchema": {
    "type": "object",
    "properties": {
      "city": {
        "type": "string",
        "description": "城市名称"
      }
    },
    "required": ["city"]
  },
  "outputSchema": {
    "type": "object",
    "properties": {
      "temperature": {
        "type": "number",
        "description": "温度，单位摄氏度"
      },
      "condition": {
        "type": "string",
        "description": "天气状况，如晴、雨、多云"
      }
    }
  }
}
```

## Meta 字段与通用用途

`Meta` 字段是一个可选的、以 `_meta` 为JSON键的字段，它被协议保留，允许客户端和服务器附加额外的元数据。该字段使用 `omitempty` 标签，意味着如果其值为空，则在JSON序列化时将被省略，从而保持传输数据的简洁性。

`Meta` 字段的通用用途非常广泛，可以用于传递调试信息、跟踪ID、自定义配置或任何不被MCP核心协议定义但对特定实现有用的附加数据。它为协议提供了良好的扩展性，允许在不修改核心结构的情况下传递上下文信息。

## 工具调用处理机制

MCP SDK提供了两种处理工具调用的底层机制：`ToolHandler` 和 `ToolHandlerFor`。

`ToolHandler` 是一个低级别的API，定义为 `func(context.Context, *CallToolRequest) (*CallToolResult, error)`。使用此接口时，开发者需要手动处理 `req.Params.Arguments` 的反序列化、输入验证、结果填充和错误处理。如果 `ToolHandler` 返回一个错误，它将被视为协议错误。

相比之下，`ToolHandlerFor` 是一个泛型接口 `func(_ context.Context, request *CallToolRequest, input In) (result *CallToolResult, output Out, _ error)`。它提供了开箱即用的丰富功能，强制工具符合MCP规范。`AddTool` 函数正是使用 `ToolHandlerFor` 来实现自动化的输入验证、默认值应用、输出序列化和错误包装。当处理器返回一个普通错误时，`ToolHandlerFor` 会自动将其包装到 `CallToolResult` 中，并设置 `IsError=true`，而不是作为协议错误抛出，这使得LLM能够感知到工具执行错误并进行自我修正。
