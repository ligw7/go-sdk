## 安装SDK

要使用本SDK，首先需要通过Go模块系统进行安装。在您的项目根目录下执行以下命令：

```bash
go get github.com/modelcontextprotocol/go-sdk
```

该命令会自动将SDK添加到您的`go.mod`文件中。以下是`go.mod`文件中的相关依赖项示例：

```
module github.com/modelcontextprotocol/go-sdk

go 1.23.0

require (
	github.com/golang-jwt/jwt/v5 v5.2.2
	github.com/google/go-cmp v0.7.0
	github.com/google/jsonschema-go v0.3.0
	github.com/yosida95/uritemplate/v3 v3.0.2
	golang.org/x/oauth2 v0.30.0
	golang.org/x/tools v0.34.0
)
```

安装完成后，您就可以在代码中导入并使用`github.com/modelcontextprotocol/go-sdk/mcp`包。

## 创建MCP服务器

本节将指导您创建一个最简化的MCP服务器。我们将基于`examples/server/basic/main.go`中的示例代码进行说明。

### 基本服务器结构

首先，创建一个`Implementation`结构体实例来描述服务器的基本信息：

```go
server := mcp.NewServer(&mcp.Implementation{Name: "greeter", Version: "v0.0.1"}, nil)
```

`mcp.NewServer`函数接收两个参数：
- 第一个参数是`*Implementation`类型，必须不为`nil`，用于描述服务器的名称和版本。
- 第二个参数是`*ServerOptions`类型，可以为`nil`，用于配置服务器行为。

### 注册示例工具

接下来，注册一个示例工具。我们使用泛型函数`mcp.AddTool`来自动填充输入和输出模式：

```go
mcp.AddTool(server, &mcp.Tool{Name: "greet", Description: "say hi"}, SayHi)
```

其中`SayHi`是一个处理函数，其签名如下：

```go
func SayHi(ctx context.Context, req *mcp.CallToolRequest, args SayHiParams) (*mcp.CallToolResult, any, error)
```

该函数接收上下文、请求对象和参数，并返回结果、结构化内容和错误。

### 启动服务

最后，启动服务器。在示例中使用了内存传输通道：

```go
serverSession, err := server.Connect(ctx, serverTransport, nil)
```

`Connect`方法建立连接并初始化会话。服务器创建后，可以处理来自客户端的请求。

## 创建MCP客户端

本节将演示如何创建一个MCP客户端来连接服务器并调用功能。

### 初始化客户端

首先，创建一个客户端实例：

```go
client := mcp.NewClient(&mcp.Implementation{Name: "client"}, nil)
```

`mcp.NewClient`函数与`mcp.NewServer`类似，接收`*Implementation`和`*ClientOptions`作为参数。

### 连接服务器

使用`Connect`方法连接到服务器：

```go
clientSession, err := client.Connect(ctx, clientTransport, nil)
```

连接成功后，您就可以通过`clientSession`对象与服务器交互。

### 调用工具列表

调用`ListTools`方法获取服务器提供的工具列表：

```go
res, err := clientSession.CallTool(ctx, &mcp.CallToolParams{
	Name:      "greet",
	Arguments: map[string]any{"name": "user"},
})
```

`CallToolParams`结构体包含要调用的工具名称和参数。`CallTool`方法发送请求并返回结果。

### 完整示例

在`examples/client/listfeatures/main.go`中有一个完整的示例，展示了如何列出服务器的所有功能：

```go
if cs.InitializeResult().Capabilities.Tools != nil {
	printSection("tools", cs.Tools(ctx, nil), func(t *mcp.Tool) string { return t.Name })
}
```

此代码检查初始化结果中的能力声明，如果支持工具，则调用`Tools`方法获取所有工具。

## 常见初始化错误排查

在初始化过程中可能会遇到一些常见错误，以下是排查提示：

### Implementation为nil

最常见的错误是传递`nil`给`NewServer`或`NewClient`：

```go
if impl == nil {
	panic("nil Implementation")
}
```

确保在调用`mcp.NewServer`或`mcp.NewClient`时提供有效的`Implementation`实例。

### 输入模式缺失

当使用`AddTool`时，如果工具的输入模式为`nil`，会触发panic：

```go
if t.InputSchema == nil {
	panic(fmt.Errorf("AddTool %q: missing input schema", t.Name))
}
```

确保为每个工具定义正确的输入模式，或者使用泛型`AddTool`函数让SDK自动推断。

### 会话生命周期管理

会话的生命周期由`Connect`和`Close`方法管理。务必在使用完毕后关闭会话：

```go
defer cs.Close()
```

未正确关闭会话可能导致资源泄漏。

## 最佳实践建议

### 使用泛型AddTool

推荐使用泛型`AddTool`函数而不是直接调用`Server.AddTool`，因为它能自动处理模式推断和验证：

```go
func AddTool[In, Out any](s *Server, t *Tool, h ToolHandlerFor[In, Out])
```

这可以减少手动编写JSON模式的工作量，并确保类型安全。

### 配置ServerOptions

对于生产环境，建议配置`ServerOptions`以启用日志记录和其他功能：

```go
opts := &mcp.ServerOptions{
	Logger: slog.Default(),
	KeepAlive: 30 * time.Second,
}
```

这有助于监控服务器状态和保持连接活跃。

### 错误处理

始终检查`Connect`和其他关键方法的返回错误，并妥善处理：

```go
if err != nil {
	log.Fatal(err)
}
```

良好的错误处理可以提高应用程序的健壮性。
