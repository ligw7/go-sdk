## 简介
客户端中间件是Go MCP SDK中一个强大的机制，允许开发者在客户端请求/响应流程中插入自定义逻辑。通过`AddSendingMiddleware`和`AddReceivingMiddleware`方法，可以在不修改核心业务代码的情况下，实现诸如添加认证头、记录日志、性能监控、重试机制等功能。本文档将深入剖析`examples/client/middleware/main.go`中的示例，详细解释中间件的工作原理、使用方法和最佳实践。

## 中间件核心机制
MCP SDK中的中间件机制基于函数式编程思想，允许将一个`MethodHandler`（方法处理器）包装成另一个`MethodHandler`。`MethodHandler`是处理MCP消息的核心函数，其签名如下：
```go
type MethodHandler func(ctx context.Context, method string, req Request) (result Result, err error)
```
中间件本身是一个函数，它接收一个`MethodHandler`作为参数，并返回一个新的`MethodHandler`。这种设计模式被称为“高阶函数”，它使得中间件可以像“洋葱”一样层层包裹，形成一个处理链。

## 发送与接收中间件
SDK提供了两种类型的中间件，分别作用于请求流程的不同阶段：

### 发送中间件 (AddSendingMiddleware)
`AddSendingMiddleware`用于在客户端**发送请求之前**插入逻辑。它接收一个或多个`Middleware`函数，并将它们应用到当前的发送方法处理器上。中间件的执行顺序是从右到左，即最先注册的中间件最先执行。

例如，`c.AddSendingMiddleware(m1, m2, m3)`会将方法处理器包装为`m1(m2(m3(handler)))`。这使得`m1`可以最先处理请求，例如添加一个进度令牌。

在`examples/client/middleware/main.go`中，`addProgressToken`就是一个典型的发送中间件，它为每个出站请求添加一个递增的进度令牌。

### 接收中间件 (AddReceivingMiddleware)
`AddReceivingMiddleware`用于在客户端**接收到请求之后**插入逻辑。它同样接收一个或多个`Middleware`函数，并将它们应用到当前的接收方法处理器上。接收中间件对于处理来自服务器的请求非常有用，例如进行身份验证、请求日志记录和指标收集。

## 中间件函数签名与执行时机
理解中间件的函数签名和执行时机是编写有效中间件的关键。

### 函数签名
一个中间件函数的签名是`func(MethodHandler) MethodHandler`。它接收一个`MethodHandler`（通常命名为`h`），并返回一个新的`MethodHandler`。这个新的处理器包含了自定义逻辑，并在适当的时候调用原始的处理器`h`。

```go
func addProgressToken(h mcp.MethodHandler) mcp.MethodHandler {
    return func(ctx context.Context, method string, req mcp.Request) (result mcp.Result, err error) {
        // 在这里插入自定义逻辑，例如修改请求
        if rp, ok := req.GetParams().(mcp.RequestParams); ok {
            rp.SetProgressToken(nextProgressToken.Add(1))
        }
        // 调用链中的下一个处理器
        return h(ctx, method, req)
    }
}
```

### 执行时机
- **发送中间件**：在`ClientSession`调用`ListTools`、`CallTool`等方法后，但在请求通过传输层（如HTTP或stdio）发送出去之前执行。这是修改请求头、添加元数据或进行请求前验证的理想时机。
- **接收中间件**：在客户端从服务器接收到一个请求（如`notifications/cancelled`）后，但在该请求被SDK的默认处理器处理之前执行。这是进行身份验证、日志记录或修改响应数据的理想时机。

## 实际应用场景
中间件机制为实现各种跨领域关注点（cross-cutting concerns）提供了优雅的解决方案。

### 添加认证头
可以编写一个中间件，在每个请求的`Meta`字段中注入认证令牌（如JWT或API Key），确保所有出站请求都经过身份验证。

### 实现重试机制
可以编写一个接收中间件，当服务器返回特定错误（如网络超时）时，自动重试请求，提高系统的健壮性。

### 性能监控
可以编写一个中间件，使用`context.WithTimeout`为请求设置超时，并在`defer`语句中记录请求的耗时，用于性能分析和监控。

## 编写与注册自定义中间件
编写和注册自定义中间件是一个简单的过程。

### 编写中间件
1.  **定义函数**：创建一个函数，其参数为`mcp.MethodHandler`，返回值也为`mcp.MethodHandler`。
2.  **实现逻辑**：在返回的匿名函数中，实现你的自定义逻辑。逻辑可以是修改`req.GetParams()`、记录日志、检查上下文等。
3.  **调用下一个处理器**：在你的逻辑执行完毕后，务必调用传入的处理器`h`，并将结果返回，以确保请求链能够继续执行。

### 注册中间件
使用`Client`实例的`AddSendingMiddleware`或`AddReceivingMiddleware`方法来注册中间件。你可以一次注册多个中间件，它们会按照注册顺序（从右到左）被应用。

```go
c := mcp.NewClient(&mcp.Implementation{Name: "test"}, nil)
c.AddSendingMiddleware(addProgressToken)
// 可以继续添加更多中间件
// c.AddSendingMiddleware(anotherMiddleware)
```

## 中间件链的潜在问题
虽然中间件非常强大，但也需要注意一些潜在问题。

### 顺序依赖
中间件的执行顺序至关重要。例如，一个负责解密的中间件必须在负责日志记录的中间件之后执行，否则日志中会记录加密后的敏感数据。开发者必须仔细考虑中间件的注册顺序。

### 错误传播
如果一个中间件在执行过程中返回了错误，它会中断整个处理链，后续的中间件和原始处理器将不会被执行。因此，中间件需要妥善处理错误，决定是返回错误还是将其传递给下一个处理器。

### 性能开销
每一个中间件都会增加一定的性能开销。虽然单个中间件的开销很小，但当链很长时，累积的开销可能会变得显著。应避免在中间件中执行耗时的同步操作。

## 总结
客户端中间件是Go MCP SDK中一个灵活且强大的特性，它通过`AddSendingMiddleware`和`AddReceivingMiddleware`方法，为开发者提供了在请求/响应流程中插入自定义逻辑的能力。通过理解`MethodHandler`和`Middleware`的函数签名，以及中间件的执行时机，开发者可以轻松地实现认证、日志、监控和重试等通用功能。然而，在享受其便利性的同时，也应注意中间件链的顺序依赖和错误传播问题，以构建健壮可靠的应用程序。
