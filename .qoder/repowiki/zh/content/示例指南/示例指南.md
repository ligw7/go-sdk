## 简介
本文档旨在将 `examples` 目录中的核心示例转化为可操作的实践指南，帮助开发者快速理解并构建基于 MCP SDK 的应用。每个示例都展示了不同的功能特性：`basic/main.go` 演示了最简化的服务器搭建；`auth-middleware/main.go` 展示了认证机制的集成；`sequentialthinking/main.go` 说明了复杂会话逻辑的实现；`http/main.go` 则呈现了通过 HTTP 协议进行流式传输的配置方法。通过逐行解析和运行指导，开发者可以复制、修改这些示例以启动自己的项目。

## 基础服务器示例
该示例位于 `examples/server/basic/main.go`，展示了如何使用 MCP SDK 构建一个最简化的服务器。程序首先创建内存传输通道，初始化服务器实例，并注册一个名为 "greet" 的工具函数 `SayHi`。客户端通过连接服务器并调用该工具，实现简单的问候交互。整个流程在进程内完成，无需网络通信，适合学习 MCP 的基本工作模式。

**关键代码段解析**：
- 使用 `mcp.NewInMemoryTransports()` 创建双向内存传输，用于服务器和客户端之间的通信。
- 调用 `mcp.NewServer()` 初始化服务器，指定实现名称。
- 通过 `mcp.AddTool()` 注册工具函数，该函数接收参数并返回文本内容。
- 客户端使用 `mcp.NewClient()` 创建实例，并通过 `Connect()` 方法建立会话。
- `CallTool()` 方法用于发起工具调用，最终输出结果。

**运行方法**：
直接编译并运行该文件，预期输出为 "Hi user"。

## 认证中间件示例
该示例位于 `examples/server/auth-middleware/main.go`，演示了如何为 MCP 服务器集成认证中间件。它支持 JWT 和 API Key 两种认证方式，并通过 `auth.RequireBearerToken` 中间件对 MCP 工具访问进行权限控制。服务器提供了 `/mcp/jwt` 和 `/mcp/apikey` 两个端点，分别处理不同认证方式的请求。

**关键代码段解析**：
- 定义 `JWTClaims` 和 `APIKey` 结构体，用于存储认证信息。
- 实现 `verifyJWT` 和 `verifyAPIKey` 函数，它们符合 `TokenVerifier` 接口，用于验证令牌并返回权限信息。
- 使用 `auth.RequireBearerToken` 创建中间件，可以指定所需的权限范围（如 "read"）。
- 服务器工具如 `GetUserInfo` 和 `CreateResource` 会检查 `req.Extra.TokenInfo` 中的权限，实现细粒度的访问控制。
- 提供了 `/generate-token` 和 `/generate-api-key` 等辅助端点，方便测试。

**运行方法**：
运行程序后，可通过 `curl` 命令生成令牌或 API Key，然后在调用 MCP 工具时在 `Authorization` 头部提供认证信息。

## 顺序思维会话示例
该示例位于 `examples/server/sequentialthinking/main.go`，说明了如何实现复杂的会话逻辑。它模拟了一个“顺序思考”过程，允许用户启动一个思考会话，逐步添加想法，修订之前的步骤，甚至创建分支。该示例展示了状态管理、并发控制和资源处理的高级用法。

**关键代码段解析**：
- `ThinkingSession` 结构体定义了会话的状态，包括问题、想法列表、状态和版本号。
- `SessionStore` 使用 `sync.RWMutex` 和乐观并发控制（通过 `CompareAndSwap` 方法）来安全地管理多个会话。
- `StartThinking`、`ContinueThinking` 和 `ReviewThinking` 工具分别处理会话的开始、继续和回顾。
- `ThinkingHistory` 函数实现了 `ReadResource` 接口，允许通过自定义 URI（如 `thinking://session_123`）访问会话数据。
- 服务器支持通过 HTTP 或标准输入/输出运行，由 `httpAddr` 标志控制。

**运行方法**：
不带参数运行时，程序通过标准输入/输出与客户端交互。若指定 `-http` 标志，则启动 HTTP 服务器，可通过 HTTP 客户端进行调用。

## HTTP传输配置示例
该示例位于 `examples/http/main.go`，展示了如何配置 MCP 通过 HTTP 协议进行流式传输。程序可以作为服务器或客户端运行。作为服务器时，它监听指定端口，通过 `mcp.NewStreamableHTTPHandler` 处理请求；作为客户端时，它连接到服务器并调用远程工具。

**关键代码段解析**：
- 使用 `flag` 包解析命令行参数，区分服务器和客户端模式。
- `runServer` 函数创建 MCP 服务器，注册 `cityTime` 工具，并使用 `mcp.NewStreamableHTTPHandler` 创建 HTTP 处理器。
- `runClient` 函数创建 MCP 客户端，连接到服务器，列出可用工具，并依次调用 `cityTime` 工具获取不同城市的时间。
- `loggingHandler` 中间件（在 `logging_middleware.go` 中定义）为 HTTP 请求添加日志功能。

**运行方法**：
首先在终端中运行 `go run main.go server` 启动服务器。然后在另一个终端中运行 `go run main.go client` 启动客户端，客户端将自动连接服务器并获取时间信息。

## 修改建议与扩展实践
为了帮助开发者将这些示例应用于实际项目，以下提供一些修改建议：

### 扩展基础服务器以支持数据库后端
可以将 `basic/main.go` 中的内存状态持久化到数据库中。例如，将 `SayHiParams` 的问候记录存储到数据库：
1. 引入数据库驱动（如 `github.com/go-sql-driver/mysql`）。
2. 在 `main` 函数中初始化数据库连接。
3. 修改 `SayHi` 函数，在返回响应前将 `Name` 和时间戳插入数据库表。
4. 添加错误处理，确保数据库操作失败时能正确返回错误。

### 增强认证中间件的安全性
`auth-middleware/main.go` 中的认证信息存储在内存中，生产环境应使用数据库。建议：
1. 将 `apiKeys` 变量替换为数据库查询。
2. 使用环境变量存储 `jwtSecret`，避免硬编码。
3. 为 API Key 添加过期时间字段，并在验证时检查。

### 优化顺序思维会话的存储
`sequentialthinking/main.go` 使用内存存储会话，重启后数据会丢失。可以：
1. 将 `SessionStore` 的后端替换为 Redis 或 MongoDB，实现会话的持久化。
2. 为 `ThinkingSession` 添加用户 ID 字段，实现多用户隔离。

### 增加HTTP示例的健壮性
`http/main.go` 的客户端在连接失败时会直接退出。可以：
1. 添加重试机制，当连接失败时进行指数退避重试。
2. 增加工具调用的超时控制，使用 `context.WithTimeout`。

通过以上修改，开发者可以将这些教学示例转化为生产就绪的应用。
